# Mリーグ モンテカルロシミュレーター仕様

## 1. 目的

Mリーグの現行レギュレーションをモデル化し、
仮想的なリーグ戦を多数回実行する。

主な分析目的は以下とする。

- レギュラーシーズン順位と最終順位の関係を分析する
- レギュラーシーズン上位チームが後続フェーズで
  どの程度有利になるかを検証する
- 各フェーズ間のポイント・順位の相関を分析する
- シミュレーション回数を増やし、結果の分布を確認する
- 持ち越し率や順位アドバンテージを変更した場合の影響を比較する

本シミュレーションは実際の試合結果を精密に再現することではなく、
一定の確率モデルの下でレギュレーションの影響を分析することを目的とする。


## 2. 用語

本プロジェクトでは以下の用語を使用する。

### 得点（score）

麻雀終了時の実際の持ち点。

例：

- 25,000点
- 30,000点
- 50,000点
- -15,000点

4人の得点合計は必ず100,000点とする。


### 素点（base point）

得点を30,000点返し・1,000点=1ptとしてポイント化したもの。

計算式：

base_point = (score - 30000) / 1000

例：

- 25,000点 → -5.0pt
- 30,000点 → 0.0pt
- 50,000点 → +20.0pt
- -15,000点 → -45.0pt

4人の素点合計は必ず -20.0pt となる。


### 順位点（rank point）

着順に応じて加算するポイント。

- 1着: +50.0pt
- 2着: +10.0pt
- 3着: -10.0pt
- 4着: -30.0pt

4人の順位点合計は +20.0pt となる。


### Mリーグポイント

素点と順位点を合計した最終的なポイント。

m_league_point = base_point + rank_point

1半荘における4人のMリーグポイント合計は必ず0.0ptとなる。


## 3. 1半荘の処理

1半荘は以下の順序で処理する。

1. 対戦する4チームを決定する
2. 4チームの着順を抽選する
3. 4チームの得点を生成する
4. 得点を素点へ変換する
5. 順位点を加算する
6. チームごとのMリーグポイントを返す


## 4. 順位抽選

### MVP

最初は4チームの着順を同一確率で抽選する。

- 同一チームが複数順位に入ってはならない
- 必ず1着〜4着まで1チームずつ割り当てる

### 将来的な拡張

チームごとに強さを表す重みを設定し、
着順抽選の確率へ反映できる構造とする。


## 5. 得点生成

得点は以下の条件を全て満たすこと。

- 1着得点 > 2着得点 > 3着得点 > 4着得点
- 4人の得点合計 = 100,000点
- 全得点を100点刻みとする
- 同点は認めない
- 同点または制約違反が発生した場合は再生成する
- 現実離れした極端な得点は除外する

得点候補は暫定的に以下の正規分布を利用する。

- 平均: 25,000点
- 標準偏差: 18,000点

平均25,000点は得点合計100,000点から決まる制約である。
標準偏差18,000点はシミュレーション上の仮定であり、
Mリーグ公式ルールではない。

得点の上下限については実装時に決定する。

将来的に実データを用いて分布を調整する可能性がある。


## 6. 同点の扱い

実際のMリーグには同着時の順位点分配ルールが存在するが、
本シミュレーションでは簡略化のため考慮しない。

同点の得点が生成された場合は、その得点生成を無効とし再生成する。


## 7. フェーズ構成

### レギュラーシーズン

- 参加: 10チーム
- 1チームあたり120半荘
- 上位6チームがセミファイナルへ進出

### セミファイナル

- 参加: 6チーム
- 1チームあたり20半荘
- 上位4チームがファイナルへ進出
- レギュラー終了時ポイントの50%を持ち越す

### ファイナル

- 参加: 4チーム
- 1チームあたり16半荘
- セミファイナル終了時ポイントの50%を持ち越す


## 8. 持ち越しポイント

基本持ち越し率は50%とする。

小数第二位以下について、
ポイントが増える方向へ調整して小数第一位までとする。

例：

123.1 / 2 = 61.55 → 61.6pt
-123.1 / 2 = -61.55 → -61.5pt

Python標準の round() に依存せず、
このルールを明示的に実装する。


## 9. フェーズ実行

フェーズ処理は可能な限り共通化する。

想定する共通処理：

simulate_phase()

フェーズごとに以下を変更可能な構造とする。

- 参加チーム
- 半荘数
- 持ち越し率
- 通過チーム数


## 10. シーズン結果

各シーズン・各チームについて最低限以下を保存する。

- シーズン
- チーム
- レギュラー順位
- レギュラーポイント
- セミファイナル順位
- セミファイナルポイント
- ファイナル順位
- ファイナルポイント

進出していないフェーズについては、
欠損値として扱える構造とする。


## 11. 複数シーズンシミュレーション

1シーズンのシミュレーションを任意回数実行できること。

想定試行回数：

- 1,000シーズン
- 10,000シーズン

試行回数は変更可能とする。


## 12. 分析

シミュレーション結果から以下を分析可能とする。

- レギュラー順位別の最終順位
- レギュラー順位別の優勝率
- ファイナル進出率
- 順位変動
- 各フェーズ間のポイント相関
- 各フェーズ間の順位相関
- 平均順位

必要に応じて pandas DataFrame に変換する。


## 13. 将来的な拡張

MVP完成後、以下を追加できる構造とする。

- チームごとの強さ
- 持ち越し率の変更
- レギュラー順位による追加ポイント
- レギュラー1位のみ持ち越し率を変更
- 得点分布の変更
- 実データを利用したパラメータ調整
- 複数レギュレーション間の比較


## 14. MVPで扱わないもの

以下はMVPでは扱わない。

- 同着時の順位点分配
- 選手個人単位の能力
- 選手の登板選択
- 麻雀の局単位のシミュレーション
- 押し引き等の戦術
- チーム状況による打ち方の変化
- 実際の牌山・配牌・ツモ
